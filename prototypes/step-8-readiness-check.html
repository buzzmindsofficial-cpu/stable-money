      How this works — no black box

      This demo uses deterministic rules + template-based language generation — not a large language model. In production, the same transparency requirement would apply to any model: every output must be traceable to the user's own answers.

      1 · The scoring rules (automation logic)
      QuestionAnswer → pointsWhy

      Could you manage an emergency without this money?Yes +2 · Probably +1 · No −10 (hard gate)Liquidity safety is non-negotiable.

      Bands: ≥ +5 → Ready · +2 to +4 → Almost · < +2 or any hard gate → Not yet. A hard gate always wins over the total.

      2 · The language templates (“prompts”)

      Each result is assembled from fixed templates filled with the user's answers — the closest thing here to a “prompt”:

      SUMMARY = "You have {savings_phrase}, and you feel
{emergency_phrase} about handling an emergency
without this money. Locking money away feels
{comfort_phrase} to you."

STRENGTH  := "You have savings set aside beyond
  your emergency needs."            // if q1 = yes
CONCERN   := "You're not certain the savings are
  truly spare — that's exactly the right thing
  to be unsure about."               // if q1 = notsure
TENSION   := "You said you have spare savings but
  also that an emergency would be hard — those
  two don't quite line up, and it's worth
  pausing on which is truer."        // if q1=yes & q2=no

      If this were LLM-powered, the system prompt would carry the same hard constraints: never name a product · never say "you should invest" · hard-gate emergency-money answers · always offer "remind me later" — plus a verbatim limitations disclosure. Deterministic templates were chosen for the demo because financial-context outputs must be auditable word-for-word.

      3 · Example inputs → outputs

      Confident repeater (yes / yes / 5 / medium / safety) → Ready: “You have savings beyond your emergency needs, and you're confident about handling an emergency without this money…” → CTA: proceed to Two-Tap Rebook.

      Cautious saver (yes / probably / 3 / short / easy access) → Almost: one solid strength plus two open questions → CTA: read the liquidity explainer, then decide.

      Stretched budget (no / no / 2 / short / safety) → Not yet (hard gate): supportive copy, no invest CTA, reminder offered, distress note shown.

      4 · Edge cases handled
      • All “not sure” / no positive signals: → Not yet — “almost” requires at least one solid strength, otherwise uncertainty itself is the signal.
      • Contradiction (spare savings = yes, emergency = no): tension paragraph names it explicitly instead of averaging it away.
      • Skipped questions: allowed; result labeled “partial reflection” and scored on answered questions only.
      • Distress pattern (no + no): supportive note, invest CTA removed entirely.
      • Retake: one tap, no judgment copy (“answers change — that's fine”).
      • Timeout / abandonment: nothing is stored; no follow-up nag is triggered by an incomplete check.
      5 · Safety guardrails
      • No product names, rates, or issuer mentions anywhere in the flow.
      • The words “you should invest” (or equivalents) never appear in any template.
      • Hard gates on emergency-money answers cannot be overridden by other scores.
      • Limitations disclosed upfront and repeated at result (“not financial advice”).
      • All processing is client-side; answers never leave the page (demo) / device (production intent).
      • “Remind me later” is always present — waiting is designed as a first-class outcome.
